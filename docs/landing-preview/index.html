EXAMPLES FROM REPOSITORY REVIEW

What can a review surface?

These examples describe repository review,
not the complete scope of local checks.

01 / SAFETY

What needs a closer look?

Credential-shaped text, binaries, install hooks and process signals.

02 / PHISHING

What may be misleading?

Lookalike domains, shortlinks and credential-harvest wording.

03 / SUPPLY CHAIN

What does it pull in?

Dependencies, lockfiles, install hooks and version drift.

04 / AI & AGENTS

What directs the agents?

MCP servers, agent instructions, prompts and workflows.

05 / TELEMETRY

Network strings, webhook endpoints and collection signals.

06 / ARCHIVE

What is inside the ZIP?

Traversal, symlinks, compression hazards and path tricks.

CONFIDENCE NEEDS LIMITS

A useful signal.
Not a safety certificate.

Sentinel cannot prove that a repository is safe.

Static analysis does not reveal every threat or predict all runtime behavior. Findings help guide deeper review; they do not replace it.

Review reports before sharing them. Sanitization is best-effort, not a guarantee that every secret or personal detail is removed.
